# 第一部分：云端微调（AutoDL 租卡一天）

## 1.1 本地一次性校验（可选，确认数据没问题）

PowerShell（Windows）：

```powershell
python -m pytest D:\mashu77\workspace\project1\p3_model_finetune\tests\test_data_format.py -v --rootdir=D:\mashu77\workspace\project1\p3_model_finetune -p no:cacheprovider
```

预期输出末尾：`5 passed`。

## 1.2 租卡并开机

1. 登录 AutoDL 控制台 →「算力市场」；
2. 选择实例：**RTX 3090 或 4090（24GB）**，地区任选（选有货的）；
3. 镜像选择：**PyTorch 2.x + CUDA 12.x 基础镜像**（自带 conda 与驱动）；
4. 开机，复制 SSH 登录命令（形如 `ssh -p 23456 root@connect.xxx.seetacloud.com`），并设置密码。

登录：

```bash
ssh -p <SSH端口> root@<云IP>
```

验证 GPU：

```bash
nvidia-smi
```

预期：显示 `NVIDIA GeForce RTX 4090`（或 3090）、显存约 24GB。

## 1.3 云端安装环境并下载模型

```bash
cd /root/autodl-tmp
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e .
pip install modelscope
modelscope download --model Qwen/Qwen2.5-1.5B-Instruct --local_dir /root/autodl-tmp/models/Qwen2.5-1.5B-Instruct
```

验证：

```bash
llamafactory-cli version
ls -lh /root/autodl-tmp/models/Qwen2.5-1.5B-Instruct
```

预期：版本号正常；模型目录含 `config.json`、`model-*.safetensors`（合计约 3.2GB）、`tokenizer.json`。

# 第二部分：本地部署（WSL2 + vLLM，方案二）

> 主路径：`local_train/本地WSL2-vLLM部署手册.md`（第 0~7 节，命令精确到每一步）。
> 备选路径：Windows 原生 Ollama（GGUF）见下方 2.1~2.7。

## 2.0 快速开始（主路径）

在 WSL2（Ubuntu）内：

```bash
bash /mnt/d/mashu77/workspace/project1/p3_model_finetune/local_train/setup_wsl2_vllm.sh
cp -r /mnt/d/p3/models/qwen1.5b-merged ~/p3/models/
bash /mnt/d/mashu77/workspace/project1/p3_model_finetune/local_train/serve_vllm_wsl2.sh
```

Windows 验证：`curl.exe http://127.0.0.1:8100/v1/models` → `finetuned-qwen`。

## 1.9 云上 vLLM 部署（可选加分，与讲义第五章一致）

训练/导出保留 bf16 合并模型 `/root/autodl-tmp/p3/output/qwen1.5b-merged` 后，在云上直接起 vLLM：

```bash
uv pip install vllm -i https://pypi.tuna.tsinghua.edu.cn/simple
nohup vllm serve /root/autodl-tmp/p3/output/qwen1.5b-merged \
  --served-model-name finetuned-qwen \
  --port 8100 \
  --api-key sk-p3-demo \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85 \
  > /root/autodl-tmp/vllm.log 2>&1 &
```

本地访问（SSH 隧道，把云端 8100 映射到本地）：

```powershell
ssh -L 8100:127.0.0.1:8100 -p <SSH端口> root@<云IP>
```

然后本地 `curl.exe http://127.0.0.1:8100/v1/models` 即可；演示与评估脚本不变。

## 2.7 常见问题

| 现象 | 处理 |
| --- | --- |
| `curl` 连接失败 | 确认 Ollama 在运行（`ollama list` 或托盘图标）；确认 `OLLAMA_HOST=127.0.0.1:8100` 已设置并重启 Ollama |
| 端口被占用 | `netstat -ano | findstr 8100` 查看占用进程，换端口或结束进程 |
| `ollama create` 报找不到文件 | 确认 `D:\p3\models\qwen1.5b-q4_k_m.gguf` 存在；Modelfile 中 FROM 用正斜杠 `D:/p3/models/...` |
| 模型回答慢/内存高 | 把 `deploy/Modelfile` 中 `num_ctx` 降到 1024 后 `ollama rm finetuned-qwen` 再 `ollama create` |
| 中文乱码 | PowerShell 先执行 `chcp 65001`，或把终端编码切到 UTF-8 |
| 想切回 DeepSeek | 本项目本地演示不涉及 P1 线上切换；对比基线固定为 DeepSeek 官方 API |
