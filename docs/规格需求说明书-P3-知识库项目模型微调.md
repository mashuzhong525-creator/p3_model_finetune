# 规格需求说明书：P3 知识库项目模型微调（绿建/双碳）

> 版本：v0.1（草稿）｜日期：2026-08-19｜状态：待确认开放问题后定稿
> 来源：`docs/任务框架-P3-模型微调.md`、`docs/需求文档-绿建双碳AI实战项目-v1.md`、`docs/产交流会议纪要.md`、P1 接口契约（§10 已冻结）
> 关联项目：P1 知识库管理平台（已上线，4核4G 云服务器）

## 1. 背景与动机

课程实战要求从《项目实战》第 4 部分选择 1 个模型微调项目，且必须与所选系统项目（P1 知识库管理平台）结合。P3 的目标是微调开源模型，提升其在知识库场景的作答质量（术语适配、忠实性、多片段整合、证据引用、拒答），并在本地 WSL2 vLLM 提供 OpenAI 兼容接口，完成「微调前 vs 微调后」评估对比演示（P1 线上不切换）。

## 2. 目标（可度量）

- G1：训练数据 ≥300 条问答对（train/val = 9:1），按五能力分层，格式通过 LLaMA-Factory 校验。
- G2：真实完成至少一轮训练（非仅脚本），产出训练日志、loss 曲线、LoRA 适配器权重（合并模型视可行性）。
- G3：金标准评估集 ≥50 条；M1 证据引用命中率 ≥95%、M2 结构化合规率 100%、M3 反幻觉遵守率 ≥80%、M4 评估覆盖 100%（S2 自测口径；S3 如实标注）。
- G4：微调模型在本地 WSL2 vLLM 提供 OpenAI 兼容接口，可现场演示「DeepSeek ↔ finetuned-qwen」对比（`/v1/models` + 对话调用）。
- G5：交付物按课程命名规范整理，含 README 与运行说明、截图清单。

## 3. 非目标

- 不做 7B 以上全参微调；仅 LoRA/QLoRA 小模型。
- 不做生产级安全、多租户、高并发；演示级即可。
- 不覆盖与绿建/双碳无关的行业语料。
- 不在本地 Windows 部署 vLLM（官方不支持）；本地只负责训练。
- 不为了"保护本地电脑"而租 GPU 云（单次训练损耗可忽略，见体检报告结论）。

## 5. 功能需求

### FR-P3-1 训练数据

- 领域：绿色建筑评价标准（2019/2014/2024）、双碳政策、碳核算方法、节能绿建设计。
- 五能力分层与目标占比：术语适配 20%、忠实回答 25%、多片段整合 15%、证据引用 20%、资料不足拒答 20%。
- 规模：≥300 条问答对，train/val = 9:1；每条含 `instruction`（问题）、`input`（检索片段，可空，片段以 `[证据N]` 编号）、`output`（标准答案，遵守 C-RAG-ANSWER 输出契约）。
- 过程要求：样本生成与校验使用的提示词统一保存在 `prompts/`；生成过程记录保存于 `docs/`。
- 当前状态：**已生成 300 条问答对**（术语适配 60、忠实回答 75、多片段整合 45、证据引用 60、拒答 60），alpaca 格式，位于 `data/`；已按 9:1 划分 `train.json`（270）/ `val.json`（30）。素材基于公开资料整理，来源见 `data/素材语料库.md`；拒答层冲突样本为构造示例。

### FR-P3-2 训练

- 使用 LLaMA-Factory CLI（yaml 配置）启动 **LoRA bf16** 训练（1.5B，无需 QLoRA）。
- 输出：训练日志、loss 曲线、适配器权重；时间允许时合并导出模型。
- 训练参数（epochs、lr、max_length、batch_size 等）在实现阶段确定并记录到 README。
- 环境：新建独立 conda env（建议 `finetune`），避免污染现有环境；模型从 ModelScope/HF 镜像下载到 `D:\ai_models`。

### FR-P3-3 评估

- 金标准 ≥50 条，按五能力分层，每条含条件化字段（如 `requires_caution`）。
- 四指标：M1 证据引用命中率 ≥95%；M2 结构化合规率 100%；M3 反幻觉遵守率 ≥80%；M4 评估覆盖 100%。
- 分级验证：S1 静态校验（schema + 引用编号合法）→ S2 行为自测（mock LLM，纯标准库）→ S3 实机（真实 LLM + 人工抽检 20%）。
- 纪律：S3 未跑必须标注「未经实机」，不以 S2 冒充。
- 产出：微调前（DeepSeek/基座）vs 微调后四指标对比报告。

### FR-P3-4 本地部署与演示（v4：P1 线上不切换）

- 本地 WSL2（Ubuntu）安装 vLLM，加载 bf16 合并模型 `finetuned-qwen`（`vllm serve --port 8100`，OpenAI 兼容端点 `POST http://127.0.0.1:8100/v1/chat/completions`，Bearer 鉴权）。
- 演示方式：本地问答调用 + `eval_runner.py` 对比 DeepSeek ↔ finetuned-qwen，产出四指标对比报告。
- P1 线上接入：本次不做；如后续需要，通过内网穿透（frp/ngrok）或把 GGUF 双部署到 4C4G 实现（可选）。

### FR-P3-5 文档与交付

- README：训练、部署、评估三步说明。
- 截图清单：数据格式示例、训练日志/loss 曲线、`/v1/models` 与对话调用、微调前后对比报告、本地 vLLM 演示。

## 6. 与 P1 的接口契约（冻结，2026-08-17）

- 端口约定：LLM=8100、BGE-M3=8200、reranker=8300（本方案推理在本地，端口沿用 8100；向量/重排视 P1 现状决定）。
- env 映射：

| P1（.env / .env.prod） | P3 文档约定 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` | `TEXT_LLM_OPENAI_API_KEY` | 在线判定：非空即在线 |
| `LLM_BASE_URL` | `TEXT_LLM_OPENAI_API_BASE` | 本地演示用 `http://127.0.0.1:8100/v1` |
| `LLM_MODEL` | `TEXT_LLM_DEFAULT_MODEL` | 对应服务 `--served-model-name` |
| `EMBEDDING_API_URL` | `BGE_M3_URL` | 远程 BGE-M3（可选） |
| `RERANK_API_URL` | `BGE_RERANKER_URL` | 远程 reranker（可选） |

- 训练数据 `output` 必须遵守 P1 `c_rag_answer.prompt` 输出契约（六条规则，见 `prompts/P1-C-RAG-ANSWER-输出契约.md`）；违反会拉低 P1 线上 M1/M2/M3。
- 向量维度切换（hash 256 → BGE-M3 1024）需清空 `data/vectors` 并重新导入。
- 变更契约需 P1+P3 协同评审；P1 `tests/test_prompts.py` 锁定关键条款。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 本地训练资源 | 1.5B LoRA bf16 峰值约 5GB 显存，8GB 够；16GB 内存训练前关闭大型后台应用 |
| 本地推理资源 | 1.5B bf16 约 3.2GB，8GB 显卡可跑（vLLM 需 WSL2）；Ollama 弃用（仅存档） |
| P1 线上隔离 | 本地推理无法被云端 P1 直接访问；本次演示不接 P1 线上，如需接入走内网穿透或双部署 |
| transformers 5.x 与 LLaMA-Factory 不兼容 | 新建独立 env，由 LLaMA-Factory 安装其配套依赖 |
| 模型/依赖下载失败 | ModelScope 镜像（模型放 D:\ai_models）、HF 镜像、离线包 |
| 本地 16GB 内存偏紧 | 训练前关闭大型后台应用；必要时调小 batch/max_length |
| 训练数据质量影响效果 | 五能力分层 + 拒答样本保证；先小规模（如 50 条）验证再全量 |
