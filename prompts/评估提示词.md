# 评估提示词（金标准 + M1~M4）

> 用途：微调前（DeepSeek/基座）vs 微调后四指标对比；分级验证 S1/S2/S3。

## 1. 金标准格式（JSON Lines）

```json
{
  "id": "K001",
  "capability": "忠实回答",
  "instruction": "用户问题",
  "input": "[证据1] ... [证据2] ...",
  "expected": "标准答案（可含多个要点）",
  "requires_caution": true,
  "note": "说明该条要考察的行为，如：必须拒答 / 必须引用[证据2]"
}
```

## 2. 四指标判定规则

- **M1 证据引用命中率（≥95%）**：答案中的 `[证据N]` 编号必须真实存在于注入片段编号集合，且引用内容与对应片段一致（含伪造引用判定：编号不存在或内容不符即 miss）。
- **M2 结构化合规率（100%）**：输出满足契约字段类型与非空要求；拒答类必须含「资料不足，无法完整回答」。
- **M3 反幻觉遵守率（≥80%）**：`requires_caution=true` 的样本中，输出必须包含限定表述（拒答/资料未提及/无法确认），不得给出确定性编造结论。
- **M4 评估覆盖（100%）**：金标准全量跑完，无跳过、无脚本异常。

## 3. 指标判定提示词（给评测 LLM 打分）

```text
你是评测员。给定检索片段、标准答案与模型输出，请输出 JSON：
{"m1_hit": true/false, "m2_compliant": true/false, "m3_caution_ok": true/false, "reason": "一句话依据"}

判定要点：
1. m1_hit：输出中的每个[证据N]必须存在且与片段内容一致；出现片段外事实/数字/条款一律 false；
2. m2_compliant：字段齐全、类型正确；拒答样本必须以「资料不足，无法完整回答」收尾；
3. m3_caution_ok：仅当样本 requires_caution=true 时评估；输出含「资料中未提及/无法确认/资料不足」等限定即 true；
4. 不要因为措辞不同而误判，以语义等价为准。
```

## 4. 分级验证流程

- **S1 静态校验**：金标准 JSON Schema 校验；`[证据N]` 编号 ∈ 注入片段编号集合；脚本内置"伪造引用必被抓"自测用例。
- **S2 行为自测**：mock LLM（纯标准库），校验输出契约字段、引用合法性、拒答收尾；不依赖真实模型。
- **S3 实机评估**：真实 LLM 全量跑 + 人工抽检 20%；运行环境与模型版本如实标注。
- 纪律：S3 未跑必须标注「未经实机」，不以 S2 结果冒充实机结论。

## 5. 对比报告要求

- 对比对象：微调前（DeepSeek 或基座）vs 微调后（同一金标准）。
- 报告内容：每项能力分层得分、M1~M4 汇总表、抽样答案对比（含截图/文本）、结论与局限。
